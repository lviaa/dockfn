# ADR 0002：手动发现本机 Web 服务

- 状态：已接受
- 日期：2026-07-28

## 背景

手工填写宿主机端口足够精确，但不利于管理已经运行多个服务的 NAS。DockFN 需要提高创建入口的易用性，同时不能接管 Docker、WatchCow 或应用登记。

## 决策

DockFN 提供由管理员触发的只读发现操作。完整候选集合不进入业务配置；管理员选中候选并成功创建入口后，仅把来源类型、容器或进程名、镜像说明、网络/PID 和 WatchCow 标识保存为 AppSpec 的只读来源快照，用于列表标签和搜索，不参与控制、重绑定或对账。候选来源包括：

- 宿主机上可通过 IPv4 访问的 TCP 监听端口，包括由双栈 socket 提供的 IPv4 入口；
- Docker 已发布的 IPv4 宿主机端口；
- 通过监听 PID、cgroup 和 PID namespace 归属到 `network_mode: host` 容器的端口；
- 仅作为名称、协议、路径和图标建议的 WatchCow 标签。

发现没有调度器、队列、后台监听或自动登记。候选只有在管理员进入核对表单并确认创建后才会成为应用配置。

权限助手只执行固定白名单内的只读命令，不执行 Docker 生命周期、卷、网络、镜像或数据操作。

重复判断使用已安装 fnOS 入口的协议、宿主机端口和路径，不使用 AppName 或显示名称相似度。WatchCow `service_port` 只标记对应容器的首选端口，不把同容器其他端口视为已登记。

## 影响

- 管理员可以快速选择候选，同时保留完全显式的创建流程。
- IPv6-only 监听和 Docker 发布地址不进入候选；监听枚举不按 socket 家族预先裁剪，而以 IPv4 HTTP/HTTPS 探测结果判定，避免遗漏双栈服务。
- 发现结果是瞬时快照，提交前的目标端口探测仍是权威检查。
- 已注册应用可以显示创建时的来源标签；来源快照不会随容器或进程变化自动更新。
- 权限助手和诊断需要区分来源不可用、包安装失败和桌面入口校验失败。
