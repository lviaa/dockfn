# ADR 0003：可变入口身份与浅层图标发现

- 状态：已接受
- 日期：2026-07-29

## 背景

fnOS 官方入口规范要求入口 ID 保持稳定，并以 appname 为前缀。随机、不可读的身份不利于用户识别和后续管理。

发现流程已经读取目标 Web 根页面，大多数服务也会通过 `<link rel="icon">` 或常见 favicon 路径提供图标。

## 决策

新登记壳以 `<LaunchID>.dkfn` 同时作为 appname 和唯一桌面入口 ID。Launch ID 为 1–27 位，以小写字母开头，只包含小写字母、数字和内部连字符；不接受数字或大写字母开头的自定义请求，留空时使用 `d` 加不可变的 12 位 AppSpec ID。

Launch ID 使用身份迁移策略：DockFN 先安装并验证新身份，再移除旧登记壳并原子保存 AppSpec。任何步骤失败都会清理替代壳并恢复旧身份。内部 AppSpec ID 和包历史键不变。

入口身份边界确定为：DockFN 提交稳定入口 ID，fnOS 负责 FN Connect 域名映射、DNS、证书和最终 URL。

服务扫描只记录已获取根页面中的同源 icon 关系，不请求或展示业务图标。选择候选进入核对页后，DockFN 才通过受认证的预览接口依次验证 WatchCow/页面提示和少量常见路径。只接受 PNG、JPEG 或受支持的 ICO，不抓取脚本、Web manifest、子页面或认证流程；全部失败时使用默认图标。

## 影响

- 入口身份可读、可编辑，并保持 fnOS 所需的稳定性。
- 身份迁移需要冲突检测、补偿清理、诊断和真机验证。
- 图标发现增加少量本机 HTTP 请求，但没有后台任务、持久化、自动登记或目标服务修改。
- `internal/app` 统一管理身份转换和迁移；包生成与 fnOS 校验调用同一个 `DesktopEntryName`。
