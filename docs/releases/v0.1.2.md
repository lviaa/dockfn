# DockFN 0.1.2

DockFN 0.1.2 修复了部分 fnOS 设备创建桌面入口时，`fnpack` 成功执行但产物文件名与应用 ID 不一致，导致创建流程错误地报告 FPK 不存在的问题。

本次发布还补充了 fnOS 登记失败的诊断信息，以及已注册应用列表和长耗时操作的使用反馈优化；不改变目标 Web 服务、容器、端口或业务数据。

## 修复

- 权限助手不再假定 `fnpack` 产物必须命名为 `<appName>.fpk`。
- 在本次创建专用的隔离输出目录中，只接受唯一的常规 `.fpk` 文件；零个或多个产物都会拒绝继续安装，并给出明确诊断。
- 产物定位失败时保留 `fnpack` 命令输出，便于定位工具链版本或打包异常。
- 安装或更新在任意阶段失败时，权限助手都会保留最近一次失败快照；已有的应用中心安装和桌面入口校验快照仍保留其更详细的内容。
- 页面不再笼统声称“已保留安装诊断”，而是直接显示后端返回的实际失败原因。
- 当权限助手不可连接时，服务发现会返回可识别的不可用状态；页面直接提示检查 DockFN helper，不再显示内部连接错误。
- 登记壳更新失败后的恢复或清理若再次失败，安装诊断会记录补偿阶段和错误，便于定位“fnOS 应用登记未完成”但诊断内容不足的问题。
- 修复新增应用复核页在受限高度下无法垂直滚动的问题。
- 已注册应用卡片为操作区固定预留四个按钮的宽度；登记异常出现“修复登记壳”按钮时，端口和状态列不再横向偏移。
- “修复登记壳”使用与“同步桌面图标”不同的图标，避免操作含义混淆。
- 删除 fnOS 应用入口期间，确认按钮会显示旋转图标和“正在移除…”，同时保持禁用以避免重复提交。

## 验证

- 增加回归测试，覆盖唯一但文件名不同的 FPK、没有 FPK 和生成多个 FPK 的场景。
- 增加回归测试，确保 `fnpack` 产物缺失或歧义时也能在诊断页获得失败快照，并验证页面显示真实错误。
- 增加前端回归测试，覆盖受限表单滚动、桌面操作区宽度、修复图标区分、权限助手不可用提示和删除中的动态反馈。
- 增加 Go 回归测试，覆盖发现 helper 不可用的错误分类，以及登记壳恢复失败的诊断记录。
- 发布前执行完整自动化验证，并为 x86_64 和 ARM64 构建、校验 FPK 产物。
- ARM64 FPK 已在 Docker QEMU 模拟的 `linux/arm64` 环境中完成创建入口流程：从 FPK 解出真实 ARM64 二进制，启动管理服务和权限助手，并模拟 `fnpack`、应用中心登记、安装目录和桌面入口校验。

## 范围说明

- 本版本不内置反向代理或任意 IP/端口转发。DockFN 继续只登记已有 HTTP/HTTPS 宿主机端口；需要访问其他局域网主机时，应通过 Caddy、Nginx 或 Traefik 等专用反代暴露为 NAS 本机稳定端口。
- ARM64 QEMU 模拟覆盖 DockFN 自身的二进制、创建、登记和校验链路，但不能替代真实 ARM fnOS 的 `fnpack` 与应用中心验证。正式发布前仍需一台 ARM fnOS 设备完成安装和创建入口冒烟测试。

## 升级说明

升级 DockFN 后重新创建此前失败的入口即可；不需要修改目标 Web 服务、容器、端口或业务数据。
