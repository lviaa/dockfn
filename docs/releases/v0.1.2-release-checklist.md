# DockFN 0.1.2 发布检查清单

状态：**待真实 ARM fnOS 冒烟测试后发布**。本清单用于合并 `codex/fix-fnpack-artifact-discovery` 后的最终检查；在全部发布门禁完成前，不创建 `v0.1.2` tag。

## 本批次内容

1. 修复 `fnpack` 已完成但产物名不等于 `<appName>.fpk` 时，DockFN 错误报告文件不存在的问题。现在只接受隔离输出目录中唯一的非空常规 `.fpk` 文件；零个或多个产物都会拒绝安装并保留命令输出。
2. 修复登记失败提示与诊断不一致的问题。安装或更新任一阶段失败都会写入最近失败快照；应用中心安装失败和桌面入口校验失败继续保留其详细快照；页面直接显示后端实际错误。
3. ARM64 已完成交叉编译、FPK 静态校验，以及 QEMU `linux/arm64` 模拟下的创建入口验证。

## 已完成门禁

- [x] `VERSION` 为 `0.1.2`，发布说明已更新。
- [x] Go 回归测试覆盖不同文件名、无产物和多产物的 `fnpack` 输出。
- [x] 前端回归测试覆盖显示实际登记错误。
- [x] Docker `make verify`：Go 测试、35 个前端测试、格式、静态检查、依赖审计和 race 检测通过。
- [x] Docker `make fpk`：生成并校验 x86_64 与 ARM64 FPK、校验和、ELF 架构、生命周期脚本、UI 资源和产物边界。
- [x] ARM64 QEMU：从 ARM64 FPK 解出真实二进制，创建入口 API 返回 `CREATED`，并检查 ownership、应用中心 manifest、`target` 链接、`ui/config` 和保存的入口 FPK。

## 发布动作（全部门禁完成后）

```sh
VERSION="$(cat VERSION)"
COMMIT="$(git rev-parse HEAD)"
BUILD_TIME="$(date -u +%Y-%m-%dT%H:%M:%SZ)"

make verify
make fpk COMMIT="$COMMIT" BUILD_TIME="$BUILD_TIME"
git tag "v$VERSION"
git push origin "v$VERSION"
```

本次明确不包含内置反向代理或任意 IP/端口转发；该类需求继续通过外部专用反代接入，不作为 0.1.2 的发布门禁。
