# DockFN 0.1.1

DockFN 0.1.1 聚焦入口标识配置、服务发现、图标体验和诊断稳定性。

## 新增

- 新增全局配置：完整 fnOS ID 模板、默认打开方式、默认用户可见范围、进入新增流程时自动扫描，以及 DockFN 图标角标开关。
- fnOS ID 模板默认是 `dkfn.{id}`，也支持 `{id}.dkfn` 等完整形式。模板必须包含一个 `{id}` 和固定标识；DockFN 不再隐式追加后缀。
- 根据应用名称自动建议可编辑的入口 ID：支持中文无声调拼音、英文小写化及特殊符号过滤。
- 新增“同步桌面图标”：按当前角标配置重新生成并安装入口壳，不探测、启动、停止或修改目标 Web 服务。
- 新增来源分组的服务发现列表，可区分 Docker、Docker Host、宿主机和已忽略服务；已忽略候选会保存到本地配置。

## 优化

- 新增应用流程完善为“发现服务 → 核对信息 → 创建应用”，创建阶段展示安装与入口校验状态，成功后可关闭或继续创建。
- 新增应用弹窗不再因点击外部遮罩关闭，避免误触丢失填写内容。
- 图标支持从当前访问路径识别、填写相对或完整 URI、上传图片，并提供预览与默认图标回退。
- 已注册应用的来源信息和操作按钮优化为紧凑标签与悬停提示；移动端列表布局同步优化。
- 诊断中心只显示有内容的最近扫描、最近安装失败和合并运行日志；空记录不再显示为不可查看的条目。
- 诊断接口对空数据稳定返回数组，前端兼容旧后端返回的空值，并在读取失败、超时或中断时于弹窗内显示错误和重试入口。
- Windows 打包入口统一移至 `scripts/build-fpk.ps1` 与 `scripts/build-fpk.cmd`，产物固定输出到 `dist/fpk`。

## 修复

- 修复同步桌面图标后缺少明确过程与完成提示的问题。
- 修复诊断弹窗请求失败后持续显示加载状态的问题。
- 修复诊断列表只有一条记录时被拉伸占满弹窗高度的问题。
- 修复无运行日志时 `logs: null` 导致诊断页面渲染异常的问题。

## 兼容性与注意事项

- 0.1.0 已注册应用的 fnOS ID 保持不变；旧记录未保存角标字段时按“显示角标”兼容处理。
- 修改全局 ID 模板不会重命名已注册应用；默认值只影响后续新增应用。角标设置会在新建、重新保存或“同步桌面图标”后应用。
- 同步桌面图标会重新安装入口壳，fnOS 桌面图标可能短暂刷新。若仍显示旧图标，请关闭并重新打开桌面；必要时刷新页面或清除图片缓存。
- 卸载 DockFN 时仍默认保留已注册入口。本版本不包含批量移除入口的断点续接或回滚机制。

## 构建与发布前验证

```powershell
# Windows PowerShell
.\scripts\build-fpk.ps1
```

或在 POSIX 环境执行：

```sh
make verify
make fpk
```

发布文件位于：

```text
dist/fpk/dockfn-0.1.1-x86_64.fpk
dist/fpk/dockfn-0.1.1-arm64.fpk
dist/SHA256SUMS
```
